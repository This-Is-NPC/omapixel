# The format

This is the executable contract implemented by the production codec. Version 2
is the current and only supported document format; there is no runtime legacy
compatibility path.

The machine-readable shape is [`format-v2.schema.json`](format-v2.schema.json).
The cross-field rules below are tested by `tests/test_format_v2.py` against the
canonical fixtures in `tests/fixtures/format-v2/`. Boundary and mutation
properties are generated by `tests/test_format_v2_properties.py`; the fixed
seed keeps failures reproducible.

## Document shape

```json
{
  "version": 2,
  "canvas": {"width": 3, "height": 2},
  "palette": [{"slot": "A", "colour": "#112233FF"}],
  "clips": [{"id": "idle", "name": "Idle", "fps": 8, "frameCount": 2}],
  "layers": [{
    "id": "background",
    "name": "Background",
    "visible": true,
    "locked": false,
    "opacity": 255,
    "mode": "normal",
    "storage": "shared",
    "cels": [{"scope": "all", "rows": ["AAA", "A.A"]}]
  }]
}
```

- `version` is exactly integer `2`; missing, fractional, string, and other versions are refused.
- `canvas.width` and `canvas.height` are positive integers no greater than 2048.
- Every object rejects unknown fields. JSON object keys must also be unique.
- `palette` is ordered and has at most 256 entries. A `slot` is one printable character other than `.`, `"`, or `\\`; C0/C1 controls and DEL are rejected, and it occurs once. `.` is implicit transparency. `colour` is uppercase or lowercase `#RRGGBBAA`.
- `clips` is non-empty. Clip IDs and names are each unique. IDs match `[a-z][a-z0-9-]{0,63}`; names are non-empty and at most 128 characters. FPS is an integer from 1 through 60, and `frameCount` is positive.
- `layers` is non-empty. Layer IDs and names are each unique. The ID is immutable identity; the name is editable presentation text. The array is the clip-wide bottom-to-top order for every clip and frame.
- Hard cardinality limits are 64 clips, 64 layers, 1024 frames per clip, 4096 total frames, 16384 total cels, and 256 palette slots. The codec checks these with `qint64` accumulation before constructing documents or iterating frame/cel ranges.
- `opacity` is one global integer from 0 through 255. There is no frame-keyed opacity in v2.
- `visible`, `locked`, `mode`, and `storage` are explicit. Modes are `normal`, `multiply`, and `screen`.
- A cel row array has exactly `canvas.height` strings, each exactly `canvas.width` characters, and every non-`.` character is a declared palette slot.
- A `shared` layer has exactly one cel with `scope: "all"`; it is used for every clip and frame.
- An `animated` layer has exactly one cel for every `(clip, frame)` pair, no more and no fewer. Its cel's `clip` must name a declared clip and `frame` must be in that clip's range.

The fixture harness reports semantic failures at the JSON path of the offending
value, for example `$.layers[1].cels` for a cel-count failure.

## Composition and quantization

Rendering visits `layers` from first to last, skipping a layer when `visible` is
false. `locked` never changes rendering; it only gates mutations. A missing cel
is invalid rather than transparent. The implicit transparent pixel and a layer
with opacity zero contribute no colour.

All arithmetic is integer and deterministic:

1. `round255(n) = floor((n + 127) / 255)` for non-negative integers.
2. Effective source alpha is `round255(palette_alpha * layer_opacity)`.
3. Premultiplied source channel is `round255(source_channel * effective_alpha)`.
4. For destination premultiplied channel `Dp` and alpha `Da`, source-over is
   `Pout = Sp + round255(Dp * (255 - Sa))` and
   `Aout = Sa + round255(Da * (255 - Sa))`.
5. Straight output channels are `0` when `Aout` is zero, otherwise the nearest
   integer to `Pout * 255 / Aout`, expressed exactly as
   `floor((Pout * 255 + Aout / 2) / Aout)` and clamped to 0..255.

`multiply` first replaces each source RGB channel with
`round255(source * destination)`. `screen` replaces it with
`255 - round255((255 - source) * (255 - destination))`. The resulting source
then uses the same source-over steps. Alpha is never multiplied by a blend mode.

Flattening to a palette is not allowed to depend on platform colour libraries.
For a non-transparent RGBA pixel and each candidate palette entry, use
`distance² = (r-r')² + (g-g')² + (b-b')² + (a-a')²`. Choose the minimum tuple
`(distance², palette_array_index, slot)`; array order wins every equal-distance
tie, and slot is a final stable tie-break. A pixel with alpha zero becomes `.`.
The selected palette entry is emitted as its slot, never as a new colour.

## Rendering surfaces

The core renderer is the only production path for PNG, ANSI, text, sprite sheets,
and Studio raster surfaces. Its default view is the composite: visible layers are
visited in array order, bottom to top. An isolated view selects one layer by ID or
name, still applying that layer's visibility, palette alpha, mode, and opacity,
but never including neighbouring layers. `locked` has no rendering effect.

PNG and ANSI retain the composed RGBA result. Text uses the same composed pixels,
then deterministically flattens each non-transparent pixel to the nearest palette
slot using the distance and tie-break rules above; transparent pixels remain `.`.
Text and ANSI refuse before building output when their hard cell or byte budget
would be exceeded. Batch scripts also have hard command-count and cumulative-
output budgets.
Checkerboard is a final opaque destination behind the completed composite for PNG
and ANSI. It is never written into a layer and has no effect on text. Sprite sheets
repeat the selected view for every clip frame, with transparent gaps between cells.

The Studio drawing surface is one C++ composed image texture per view. It does not
create one QML raster item per document layer. Onion skin asks the same compositor
for the previous frame, so it shows the previous frame's composite rather than a
single layer. Unknown palette slots are skipped without colour guessing and are
reported as renderer diagnostics; `check` also reports them before export.

## Merge and flatten operations

Core merge and flatten operations stage their complete result before changing a
document. A preview returns the staged document and a consequence report; an
apply call assigns that staged value only after every clip and frame succeeds.
Therefore cancellation or a failed guard leaves the original `Codec::write`
bytes unchanged.

The report contains frame count, affected pixels, exact palette matches,
approximated pixels, and new slots. `newSlots` is always zero for v2: an
approximation selects an existing palette entry and never adds a colour. The
reported counts are generated by the same quantizer used for the applied result,
so preview and apply reports are equal.

Merge-down selects the layer immediately above its target. The source must be
visible, the target must also be visible, and both layers must be unlocked. A
visible source cannot be removed into a hidden target because that would make the
visible result disappear. Layer order, source opacity and blend mode are composed
bottom-to-top; the baked target becomes a normal, fully opaque layer while
retaining the target's visibility. Shared output is possible only when both inputs
are shared; otherwise every clip/frame cel is retained as animated storage.

Flatten-visible writes a separate document containing one normal, fully opaque
`Flattened` layer made from visible layers only. Hidden layers are not copied and
the input document is never modified by the non-mutating operation. The output is
an explicit export artifact, so source lock flags do not silently discard visible
content. Reapplying flatten to its own output preserves the stable flattened layer
identity and serialized bytes.

## Command and state matrix

The CLI targets the file it was given. It never reads Studio session state to fill
in a missing document, clip, frame, or layer target.

| Command | Shared layer | Animated layer, `--frame N` | Animated layer, `--all-frames` | Hidden | Locked |
|---|---|---|---|---|---|
| pixel/paint/fill/edit | edits the one cel, therefore every frame | edits only `(clip,N)` | edits every cel | explicit edits are allowed; render skips it | rejected with `E_LAYER_LOCKED` |
| rename | metadata only | metadata only | metadata only | allowed | allowed |
| delete | removes the layer from the global order | same | same | allowed | rejected with `E_LAYER_LOCKED` |
| reorder | changes global order for all clips/frames | same | same | allowed | rejected with `E_LAYER_LOCKED` |
| merge | explicit source-over into target; result is shared only if both inputs are shared | expands to animated if either input is animated | same result as per-cel merge | hidden source is rejected | either locked layer is rejected |
| mode conversion | changes only `mode` metadata | same | same | allowed | rejected with `E_LAYER_LOCKED` |

`--frame` is required for an animated pixel edit unless `--all-frames` is used.
It is ignored for a shared edit but the command reports `scope=all`; it never
creates duplicate shared cels. Animated-to-shared conversion is allowed only when
all of its cels are byte-identical; otherwise it fails without writing. Shared-to-
animated duplicates the shared cel into every `(clip, frame)` pair.

Hidden is a render/export state, but content and destructive stack operations
still require `--include-hidden` when the addressed layer is hidden. Locked
protects content, metadata, ordering, duplication, removal, and merge operations;
the explicit lock-state toggle is the exception. Merge uses the source above the
target and removes the source only after every affected cel succeeds.
